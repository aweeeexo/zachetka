# Зачётка

**Зачётка** — AI-сервис, который превращает длинное учебное задание в план сдачи: этапы, дедлайны и чек-лист требований. У каждого пункта есть цитата из исходного текста, поэтому видно, что AI ничего не выдумал.

Итоговый проект курса (ШАД). Проект сдаётся в четыре этапа.

| Этап | Срок | Статус | Ссылка |
| --- | --- | --- | --- |
| 1. Презентация и защита идеи | 8 октября | ✅ сдан | _ссылка на презентацию_ |
| 2. Статический лендинг | 29 октября | ✅ готов | https://aweeeexo.github.io/zachetka/ |
| 3. Frontend MVP | 19 ноября | ✅ готов | https://aweeeexo.github.io/zachetka/app/ |
| 4. Веб-бэкенд и финальная сдача | 10 декабря | — | — |


## Этап 3. Frontend MVP

Папка [`client/`](client/) — приложение на **React 19 + TypeScript + Redux Toolkit + React Router**, сборка Vite.
Собранная версия лежит в `docs/app/` и публикуется вместе с лендингом: **https://aweeeexo.github.io/zachetka/app/**

Бэкенда пока нет: данные хранятся в `localStorage` браузера через моковый API с задержкой ответа. При первом запуске создаётся демо-проект с настоящим заданием курса.

### Как запустить

Нужен Node.js 20 или новее.

```bash
cd client
npm install
npm run dev        # http://localhost:5173
npm test           # unit- и компонентные тесты (Vitest + Testing Library)
npm run build      # проверка типов и сборка в ../docs/app
npm run lint       # ESLint
```

### Страницы (React Router)

| Адрес | Страница |
| --- | --- |
| `#/login` | Вход по email и паролю + кнопка быстрого входа в демо-аккаунт (`student@shad.ru` / `zachetka2026`) |
| `#/register` | Регистрация нового локального аккаунта с валидацией |
| `#/` | Мои проекты: поиск, карточки с прогрессом, ближайшие дедлайны |
| `#/new` | Новый проект: форма с заданием → черновик плана → сохранение |
| `#/projects/:id` | Проект: шкала этапов, чек-лист, источник пункта, редактирование |
| `#/projects/:id/ready` | Готовность к сдаче: что осталось по этапу, экспорт чек-листа в Markdown |
| `#/about` | О проекте и режим отладки |
| `*` | Страница 404 |

Используется `HashRouter`, потому что GitHub Pages не умеет отдавать `index.html` на любые пути.

### Пользовательские сценарии

1. **Задание → план.** Вставить текст задания (или нажать «Вставить пример») → «Разобрать задание» → поправить черновик (переименовать этап, поменять срок, убрать лишние пункты) → «Сохранить проект».
2. **Работа с чек-листом.** Отмечать пункты, добавлять свои, менять текст и приоритет, удалять; по кнопке «стр. N» видно цитату из исходного задания, на которой основан пункт.
3. **Готовность к сдаче.** Выбрать этап → увидеть процент и список незакрытых пунктов (сначала обязательные) → закрыть их прямо здесь → скопировать или скачать чек-лист в Markdown для README.

### Состояния интерфейса

- **Загрузка** — скелетоны на списке, черновике и странице проекта; кнопки показывают индикатор и блокируются, пока идёт запрос.
- **Пусто** — нет проектов, ничего не найдено поиском, разбор не нашёл ни одного пункта.
- **Ошибка** — сообщение с кнопкой «Повторить», всплывающие уведомления, отдельная страница «Проект не найден».
- **Режим отладки** на странице «О проекте» заставляет моковый сервер отвечать ошибкой 503 — так можно проверить все ошибки вживую. Там же можно вернуть демо-данные.

### Формы и валидация

Все формы проверяются на клиенте (`src/lib/validation.ts`): название 3–80 символов, курс до 60, текст задания от 50 символов, пункт 3–300 символов. Ошибки показываются у поля (`aria-invalid`, `aria-describedby`, `role="alert"`), фокус переходит к первому неверному полю. Те же правила повторяет моковый сервер (ответ 400), на этапе 4 их повторит настоящий.

### Архитектура

```
UI (pages, components) → dispatch(thunk) → api.* → mockApi (localStorage)
                       ← useAppSelector(selectors) ← slices
```

- **`src/api/`** — интерфейс `Api` (те же методы, что будут у REST: `GET/POST/PATCH/DELETE /api/projects…`, `POST /api/parse`) и его моковая реализация. На этапе 4 появится `httpApi` с тем же интерфейсом, остальной код менять не придётся.
- **`src/features/`** — слайсы Redux Toolkit:
  - `auth` — вход, регистрация, восстановление сессии и выход (`RequireAuth` защищает внутренние страницы);
  - `projects` — список, загрузка отдельного проекта, CRUD проектов и пунктов, «занятые» элементы; галочка ставится **оптимистично** и откатывается, если сервер ответил ошибкой;
  - `parse` — разбор задания и правки черновика;
  - `toasts` — уведомления об успехе и ошибках (реагируют на экшены других слайсов).
- API передаётся в thunk-и через `extraArgument`, поэтому в тестах его легко подменить.
- Мемоизированные селекторы (`createSelector`) — поиск, ближайшие дедлайны, общая статистика.
- **`src/lib/`** — чистые функции: разбор задания, даты, прогресс, Markdown, валидация.
- **`src/components/ui/`** — переиспользуемые компоненты: `Button`, `TextField`/`TextAreaField`/`SelectField`, `Card`, `Badge`, `ProgressBar`/`ProgressRing`, `EmptyState`/`ErrorState`/`Skeleton`, `ConfirmButton`, `Toasts`, `Icon`.
- Стили — CSS Modules и CSS-переменные с палитрой из презентации.

Разбор задания на этом этапе работает по правилам (заголовки «Этап N», строки «Срок сдачи: …», пункты списков). На этапе 4 его заменит AI на сервере; формат ответа и проверка цитат (`verifyQuote`) останутся теми же.

### Адаптивность и доступность

Сетки перестраиваются для телефона, планшета и десктопа; проверено на ширине 375 px — горизонтальной прокрутки нет. Ссылка «Перейти к содержимому», видимый фокус, подписи у всех полей, `aria-pressed` у переключателей этапов, `role="progressbar"` у прогресса, подтверждение удаления без модального окна (Esc отменяет).

### Тесты

`npm test` — 76 тестов в 13 файлах:

| Что | Файлы |
| --- | --- |
| Разбор задания, даты, прогресс, Markdown, валидация | `src/lib/*.test.ts` |
| Моковый API: CRUD, хранение, ошибки 400/404/503 | `src/api/mockApi.test.ts` |
| Слайсы и thunk-и: pending/fulfilled/rejected, оптимистичный откат, селекторы | `src/features/**/*.test.ts` |
| Компоненты: кнопки, поля, подтверждение удаления, состояния, пункт чек-листа | `src/components/**/*.test.tsx` |
| Сценарий «задание → план → проект» на странице целиком | `src/pages/NewProjectPage.test.tsx` |

Компоненты рендерятся через `renderWithProviders` (`src/test/utils.tsx`): настоящий стор и роутер, моковый API в памяти без задержек.

## Этап 2. Статический лендинг

Папка [`docs/`](docs/) — публичная страница продукта на **чистых HTML, CSS и JavaScript**, без React и без сборки.

### Что есть на странице

- Название, проблема и ценностное предложение (первый экран и блок «Проблема»).
- Как работает продукт: три шага и скриншот экрана разбора.
- **Интерактивное демо**: вставляешь текст задания → получаешь этапы, сроки и пункты с номером строки-источника. Это упрощённый разбор на регулярных выражениях прямо в браузере (в приложении на этапе 4 его заменит AI).
- Возможности, макеты интерфейса, таблица сравнения с Notion, ChatGPT и LMS, тарифы, FAQ.
- Заметный призыв к действию: кнопки «Получить ранний доступ» и форма с почтой в конце страницы.

### Адаптивность

Bento-сетка перестраивается на трёх ширинах: десктоп (> 1080 px), планшет (≤ 900 px) и телефон (≤ 640 px). На телефоне меню сворачивается в кнопку, карточки идут в одну колонку, таблица сравнения прокручивается внутри своей карточки. Проверено на ширинах 375, 768 и 1440 px — горизонтальной прокрутки нет.

### Доступность

- Семантическая разметка: `header`, `nav`, `main`, `section` с `aria-labelledby`, `footer`, один `h1`, таблица с `caption` и `scope`.
- Ссылка «Перейти к содержимому» для навигации с клавиатуры, видимый фокус у всех интерактивных элементов.
- У всех полей формы есть `<label>`, ошибки выводятся рядом с полем и озвучиваются (`role="alert"`, `aria-invalid`, `aria-describedby`).
- У содержательных картинок есть `alt`, декоративные иконки скрыты от экранных читалок (`aria-hidden`).
- Кнопка меню сообщает своё состояние (`aria-expanded`), закрывается по `Esc`.
- Контраст текста не ниже 4.5:1; анимации отключаются при `prefers-reduced-motion`.

### JavaScript (`docs/main.js`)

1. Мобильное меню.
2. Плавное появление блоков при прокрутке (`IntersectionObserver`).
3. Демо-разбор задания: `parseAssignment(text)` находит заголовки «Этап N», строки «Срок сдачи: …» и пункты списков. Показаны состояния загрузки, пустого результата и ошибки.
4. Форма раннего доступа: проверка почты на клиенте, заявка сохраняется в `localStorage` (бэкенда на этом этапе нет).

### Дизайн

Цвета и шрифт — из презентации первого этапа: бирюзовый `#0D9488`, оранжевый акцент `#EA580C`, мятный фон `#F0FDFA`, тёмно-бирюзовый текст `#134E4A`, шрифт Inter. Все цвета заданы CSS-переменными в начале `styles.css`.

### Как открыть локально

Сборка не нужна — откройте `docs/index.html` в браузере. Или запустите локальный сервер из корня репозитория:

```bash
npx serve docs
# или
python -m http.server 8000 --directory docs
```

### Публикация

Лендинг публикуется через GitHub Pages прямо из папки `docs/` ветки `main` (Settings → Pages → Deploy from a branch → `main` / `/docs`). Сборка не нужна: после каждого push страница обновляется сама. Папка называется `docs`, потому что GitHub Pages умеет публиковать без настройки только корень репозитория или папку `docs/`.
